## 1 · 战略判断：为什么「AI 资产先行」优于「先做小程序」

### 三种启动路径的 ROI 对比

| 路径 | 周期 | 单位成本 | 传播半径 | 失败成本 | 推荐度 |
|---|---|---|---|---|---|
| A. 先做小程序 | 4–6 周（开发）+ 1–2 周（审核） | 高（5–10k 开发或自学 60h+） | 微信内单点 | 高（审核驳回、留存低、收益归零） | ★★ |
| B. **AI 资产先行 → 再做小程序** | 1–2 周出首批资产 | 低（生成成本仅算力+时间） | 跨平台（小红书/抖音/视频号/朋友圈/群） | 低（资产可独立使用） | ★★★★★ |
| C. 只做资产不做小程序 | 1 周 | 极低 | 全平台 | 零 | ★★★（但丢了微信闭环） |

**核心论点**：AI 资产是**可独立工作**的最小传播单元（一张头像、一个表情、一个海报都能在朋友圈活下来），小程序是**承载资产**的容器。如果资产本身不吸引人，再好的容器也没人进。**资产先行 = 用最低成本验证"钩子"是否成立**，再决定容器形态。

### 小程序本身要解决什么

不是"网页搬运"，而是**「结果页+传播」**的容器：

```
测一测（20 题）→ 结果页（带"领取你的能量头像"按钮）→ 生成专属头像/海报
                                              ↓
                              分享到群/朋友圈（带参/带码）
                                              ↓
                              朋友点开 → 测一测（带?from=）→ 配对邀请
                                              ↓
                              二次分享 → 数据看板看 UGC
```

**对用户**：先拿到**一个值得晒的东西**（头像/海报），再决定要不要测。**对我**：用"领取头像"做留存钩子，用"配对邀请"做裂变钩子。

## 3 · 小程序规划

### 3.1 核心定位（与网页版分工）

| | 网页版 | 小程序版 |
|---|---|---|
| 定位 | 内容护城河 + SEO 入口 | **传播器** + 微信生态闭环 |
| 范围 | 全量（含深水 web-only） | 仅 L1–L3 合规子集 |
| 角色 | 自我挖掘、长期留存 | 测一发、领头像、晒出去、邀请朋友 |
| 流量入口 | 搜索/分享链接/外部 SEO | **视频号挂载** / 群裂变 / 搜一搜 / 表情包导流 |

### 3.2 信息架构

```
首页 tab
├── 测一测（20 题，5 幕人生旅程，章节流，可中断续答）
├── 问一问（核心卡分类章、四型定向筛选）
├── 每日（今日一问 + 今日签 + 表情包入口）
└── 我（结果历史 + 头像收藏 + 配对记录 + 客服反馈）

结果页（5 区块 + 1 关键新按钮）
├── ① 判定卡（型格 + 一句话）
├── ①＋ 你的能量头像（"领取你的专属头像" → 长按保存）
├── ② 假自体科普 + ③ 能量剖面 + ④ 配对邀请 + ⑤ 分享
└── ⑥ 一键生成海报（朋友圈/小红书两版）

测后 24h 召回：本地通知 + 表情包上线推送
```

### 3.3 增长闭环（核心链路）

```
[短视频/小红书] 钩子：4 型关键词 / 哪吒角色拆解
       │
       ▼
[视频号 / 群] 挂载「测一测」 / 群里发小程序卡
       │
       ▼
[小程序] 20 题 → 结果 → ① 判定 ② 头像（强留存）
       │              │
       │              └→ [保存头像] 留个人
       ▼
[分享]
   ├── 路径 A：海报到朋友圈（带太阳码）
   ├── 路径 B：双人配对卡到群（带 ?pair=）→ 朋友点开
   └── 路径 C：表情包到对话（跨场景长尾）
       │
       ▼
[小程序回流] ?from= 渠道归因 → 数据看板
```

2. **PK/配对功能 = 强裂变**（v1 弱化，截图强提醒）
   - 单人分享到朋友圈 → 平均带来 0.3 人
   - 双人 PK 邀请到群 → 平均带来 1.2–2 人（viral 系数提升 4 倍）
   - 原 v1 的"配对邀请"应改名为"能量 PK"或"双生匹配"，更对位年轻人

3. **实时数据是社会证明**——比"专业测评"更吸引人
   - 首页常驻"今日已测 XXXX 人 / 当前热门是 XX"
   - 这是 0 成本的转化率提升

4. **IP 形象统一贯穿**——测评卡、表情包、分享卡、加载页都同款
   - 我们四型各 1 IP（男阳沉默山/女阳执剑/女阴提灯/男阴镜中独坐），
   - 比 4 型共 1 IP 更具差异（每型人愿意"领走自己的"）

5. **内容即模板**——视频号/抖音/小红书每条都按这版式做
   - 钩子（前 3 秒）+ 测评主卡 + 表情包 + 数据 + 入口
   - 一套结构吃三个平台，节省内容生产成本

## 附录 B · 生图工具选型（2026-09 调研，零 token 路线）

> 背景：内置 ImageGen 按张计费（5–10 credits/张），24 枚表情包 + 16 枚头像 ≈ 200–400 credits，成本过高。
> 结论：**改用外部免费工具，我出 prompt，你在网页粘贴 → credits 消耗为 0。**

### B.4 三条避坑（必读）

1. **免费 ≠ 可商用**。即梦带水印；Leonardo 免费层图归平台；国产模型多数条款写"不得用于商业用途"。**微信表情商店上架需商用授权 → 选型前先看条款。**
2. **IP 一致性是最大难点**。纯文生图无法保证 24 枚同一 IP。三条解法：
   - Leonardo 角色一致性功能（89%）
   - **图生图**：先出 1 张定妆照 → 后续全部以它为参考图（推荐）
   - 兜底：先出图，再用美图/稿定设计统一描边与配色
3. **微信表情包规格**：主图 240×240 PNG ≤500KB，封面 240×240，横幅 750×400，面板图标 50×50 —— 最后统一裁切。
