# 音频佐证站内播放 · 技术方案 v1

> 日期：2026-08-31 ｜ 授权前提：✅ 已获切片主播恋鱼许可（授权范围建议在书面协议中明确「仅用于本站知识卡佐证片段播放 + 来源标注」）
> 目标：知识卡片「」原话点击 → **站内直接播放对应音频片段**，不跳转B站；B站入口降为次要选项。
> 决策点见第六节，确认后即可派工（预估 3–4 个工作日全量上线）。

---

## 一、目标形态（用户视角）

```
知识卡片 · 语料佐证区
「阳的信任，他就像一面墙。这个信任建设的时候，是一块砖一块砖累上去的……」
  ▶ 0:00–0:38  ▁▂▅▇▅▂▁ ← 点击即播，进度条内嵌，无跳转
  [去B站看完整视频]（次要入口，保留）
```
- 点击「」原话或播放钮 → 音频片段原地播放（不离开站点、无需安装B站）；
- 播放中该条佐证高亮；再点暂停；
- 片段结束自动停止（或顺序播放同卡下一条，待定）。

## 二、整体管线（五阶段）

```
[yt-dlp 批量拉音频轨] → [ffmpeg 按 evidence 时间戳切片 mp3] → [audio_manifest.json]
      → [托管 assets/audio/] → [前端播放器组件 + 降级跳转]
```

### Phase 1 · 素材获取（yt-dlp）
- 范围：111 张核心卡的 evidence `videoId` 去重 ≈ **60–80 个视频**（后续新卡增量拉取）；
- 命令：`yt-dlp -f "bestaudio[ext=m4a]/bestaudio" -o "raw/%(id)s.m4a" --batch-file video_ids.txt`；
- B站限速对策：`--limit-rate 2M` + 分批（每批 10 个）+ 失败重试清单；部分视频可能需要 `--cookies-from-browser chrome`（登录态）。

### Phase 2 · 切片（ffmpeg）
- **endSec 的确定（关键）**：evidence 只有 startTs；用语料逐行字幕推 end——卡片 text 对应的语料行区间 `startRow→endRow`，endSec = endRow 的 ts + 2 秒余量（语料已有逐行时间戳，`build_corpus_refined.py` 同源解析可复用）；
- 命令：`ffmpeg -ss <start> -to <end> -i raw/Bxxx.m4a -c:a libmp3lame -b:a 48k -ac 1 clips/c-<videoId>-<start>.mp3`；
- 规格：**mp3 · 48kbps · 单声道**（人声足够，≈360KB/分钟；兼容性全平台最好）；
- 异常处理：end ≤ start（行解析失败）→ 回退 start+45s；静音检测（`silencedetect`）可作二期精修。

### Phase 3 · 元数据
`data/audio_manifest.json`：
```json
{ "c-B56-0059": { "mp3": "assets/audio/c-B56-0059.mp3", "dur": 38,
                  "videoId": "B56", "startSec": 59, "endSec": 97,
                  "fallback": "https://www.bilibili.com/video/BV1EfE9z7Egt?t=59" } }
```
- key 用 `c-<videoId>-<startSec>`（与 clipId 体系对齐）；卡片 evidence.link 保留为 fallback。

### Phase 4 · 托管
- **MVP**：仓库内 `assets/audio/`，随 git push 上 GitHub Pages。体积估算：约 220 切片 × 360KB ≈ **80MB**（仓库 1GB 软限的 8%，可行；.gitignore 排除 raw/）；
- **备选（推荐二期迁移）**：Cloudflare R2（免费 10GB、媒体托管更合适、自带 CDN），前端只改资源前缀；
- ⚠️ raw/ 原始音频不入 git（体积大且无分发价值）。

### Phase 5 · 前端播放器
- 佐证区改造（qaCardHtml 的 ev-item）：「」原话行变为可点击播放行——
  `<div class="ev-item" onclick="playClip('c-B56-0059')">「原话」 <span class="ev-play">▶</span><span class="ev-dur">0:38</span></div>`
- 单例 `<audio>`（全站一个，防重叠播放）+ 进度条内嵌在该行下方；播放态高亮（晨橙左边框）；
- `manifest` 缺失/加载失败/播放出错 → **自动降级**：该行恢复为现有「▶ 去B站看原话」跳转（现有能力零损失）；
- 移动端：点击触发播放符合自动播放策略（user gesture）✓；
- 二期增强：同卡多条佐证顺序连播、播放时语速调节（0.8x/1x）。

## 三、工程交付物

| 交付物 | 说明 |
|---|---|
| `scripts/fetch_audio.py` | yt-dlp 批量下载（读 evidence videoId 清单，断点续传） |
| `scripts/build_audio_clips.py` | 解析 qa_core*.js evidence → 语料行区间推 end → ffmpeg 切片 → manifest |
| `assets/audio/*.mp3` | 切片成品（git 管理） |
| `data/audio_manifest.json` | 播放元数据（前端消费） |
| index.html 播放器组件 | 单例 audio + 降级逻辑 + 样式 |

## 五、风险与对策

| 风险 | 对策 |
|---|---|
| yt-dlp 被B站风控（下载失败/限速） | 分批慢速 + cookie 登录态 + 重试清单；授权在手也可请 UP主 协助提供原始素材（最优） |
| 仓库体积膨胀 | 监控（80MB 起步）；二期迁 R2 |
| 移动端自动播放限制 | 播放均由用户点击触发 ✓ |
| 部分佐证 end 解析失败 | 回退 start+45s；记录人工清单 |
| 小程序阶段 | mp3 资产直接复用（`<audio>` 兼容）；R2 域名需入小程序白名单 |

## 六、决策点（需用户拍板）

| # | 决策 | 推荐 |
|---|---|---|
| 1 | 切片时长策略 | 按语料行区间自动到句尾（+2s 余量），失败回退 45s |
| 2 | 音频规格 | mp3 48kbps 单声道（兼容优先，二期可升 64k） |
| 3 | 托管位置 | 先 GitHub Pages，二期迁 Cloudflare R2 |
| 4 | 播放交互 | 点「」原话即播、单例不重叠、片段结束即停；B站入口降为次要文字链 |
| 5 | 授权落纸 | 用户与 UP主 签书面授权（范围：本站佐证片段音频播放+来源标注）；协议框架可由主控起草 |
